# 成绩单透镜 · 更新与数据迁移指南

> 面向使用者（辅导员）。看完这一页你就知道：**怎么更新程序、数据在哪、
> 为什么换个 exe 数据还在、下载/重启出问题怎么办。**
>
> 对应版本：v1.8　　最后更新：2026-09-27

---

## 一、最重要的一句话

> **你的数据不在 exe 旁边，在 `%LOCALAPPDATA%\SGMS\` 里。**
> 所以**换 exe 不会丢数据** —— 前提是你别去删那个目录。

```
C:\Users\<你的用户名>\AppData\Local\SGMS\
├── users.json          账号索引（用户名、校验值；**没有明文密码**）
├── app.salt            应用级密钥盐（**别删，删了意愿/班级/档案全打不开**）
├── u_xxxxxxxx\         你的加密数据
│   ├── grades.enc              成绩
│   ├── tags.json.enc           发展意愿标签
│   ├── archive.json.enc        成长档案（学期时间轴）
│   ├── class_XX-1.json.enc     班级成绩快照
│   └── ...                     德育分、名额、AI 设置等
├── backup_exe\         更新时自动备份的旧程序（v1.8 新增）
│   └── transcript-lens_v1.7_backup.exe
├── models\             本地 AI 模型（v1.8 新增，只有你手动下过才有）
├── backup_v1.0_20260926_170351\    ← 数据迁移时自动生成的完整备份
└── backup_v1.7_20260927_...\
```

`AppData` 是 Windows 的隐藏目录。要打开它：
按 `Win + R`，输入 `%LOCALAPPDATA%\SGMS`，回车。

> ★ **`backup_exe\` 和 `models\` 都在数据目录里，不在程序目录里。**
> 原因很简单：程序可能装在 `C:\Program Files\`（那里普通用户写不进去），
> 而一个 AI 模型有 1~3GB —— 它不该混在程序文件里。

## 二、更新流程（v1.8：全自动，三步点完）

从 v1.8 起，程序可以**自己下载并替换**，你不用再去网页上下载、手动覆盖。
**但每一步都要你点一下** —— 程序不会在后台偷偷下载或安装。

### 第 1 步：点「检查更新」

```
⚙️ 设置 → 更新 → [检查更新]
```

程序联网一次（只读版本号），然后告诉你结果：

| 显示的话 | 意思 |
|---|---|
| 当前已是最新版本 (v1.8) | 没有更新的版本 |
| 当前已是最新版本 (v1.8) —— 仓库里还没有发布任何发行版 | **接口通了**，只是维护者还没发过版（不是故障，也不是网络问题） |
| 发现新版本 v1.9 | 有新版本，会自动弹出下一步的窗口 |
| 检查失败，请手动访问仓库 | 真的连不上（断网 / 被防火墙挡了） |

### 第 2 步：勾选要下载的内容 → [开始下载]

弹出的窗口长这样：

```
发现新版本 v1.9（当前 v1.8）

☑ 主程序更新（~230MB）
☐ AI 学习助手模块 - 1.5B（~1.2GB）
☐ AI 学习助手模块 - 3B（~2.8GB）

[取消]  [开始下载]
```

* **主程序**默认勾上、且不能取消 —— 更新主要就是它。
* **AI 模块**默认不勾。一个 1.2GB 的模块不该在你没注意的时候开始下。
  不勾就只更新主程序，完全不影响使用。
* 下载过程中有进度条、百分比和速度（KB/s），**随时可以点「取消」**。

> ★ **取消或断网都不会损坏现在的程序。**
> 下载全程写在一个临时文件里，**只有完整下完、并且校验通过**才会生效。
> 下到一半中断也没关系：下次再点「开始下载」会**从断点继续**。

### 第 3 步：点「立即重启」

下载完成后：

```
━━━━━━━━━━━━━━━━━━━━━━━
✅ 更新已完成（v1.9）

是否立即重启应用完成更新？
━━━━━━━━━━━━━━━━━━━━━━━
[稍后]  [立即重启]
```

**点「立即重启」**，程序会：

1. 把当前版本备份到 `backup_exe\transcript-lens_v1.8_backup.exe`；
2. 程序自动关闭；
3. 新版本替换旧版本，然后**自动重新打开**。

**点「稍后」**也不会白下 —— 新版本已经躺在临时目录里了，
**下次你手动打开程序时会自动完成替换**，不用重新下载。

> ⚠️ **备份失败就不会替换。** 万一 `backup_exe\` 写不进去
> （磁盘满、没有权限），程序会明确报错并**放弃替换** ——
> 宁可不更新，也不能让你既没有新的、也没有旧的。

### 万一没自动替换成功？

脚本会在后台重试 60 秒（因为刚关掉的程序可能还占着文件几秒）。
如果最终还是没换成，**旧版本原样还在**，程序照常能用。
排查线索在这里：

```
%TEMP%\SGMS_Update\apply_update.log
```

里面记着每一步做了什么、失败在哪一步。

## 三、常见问题

### Q1：为什么我换了个 exe，数据还在？

因为数据在 `%LOCALAPPDATA%\SGMS\`，跟 exe 是两个地方。
exe 只是"读数据的工具"，换工具不影响数据本身。

### Q2：下载中断了怎么办？

**什么都不用做，重新点一次「开始下载」就行。**

程序把没下完的部分保留在 `%TEMP%\SGMS_Update\` 里，
下次会带着"我已经有这么多字节了"去请求服务器，**从断点继续**。

如果服务器不支持断点续传（返回的是整个文件而不是"从第 N 字节开始"），
程序会**自动从头重下**，不会把新旧两段拼成一个坏文件。

### Q3：点了「立即重启」，但重启后版本号没变？

按可能性从高到低排查：

1. **看日志**：`%TEMP%\SGMS_Update\apply_update.log`
   最后一行写的是什么。`exit /b 2` = 找不到新文件，`exit /b 1` = 复制一直失败。
2. **是不是手动打开了旧图标**：如果你从固定的快捷方式 / 任务栏图标启动，
   而那个图标指向的是**另一个位置**的旧 exe，那替换的当然不是它。
   去"设置 → 更新"看一眼「当前版本」到底是多少。
3. **是不是被杀毒软件拦了**：替换 exe 这个动作会被某些安全软件盯上。
   看它的隔离区 / 拦截记录。
4. **exe 是不是在只读目录里**（例如 `C:\Program Files\` 且没用管理员权限装）。
   这种情况脚本复制不进去，日志里会写。

**不管哪种，旧版本都还在、数据都完好。** 实在不行就去发行版页面手动下载覆盖。

### Q4：界面上的版本号和实际的不一样？

v1.8 修掉了这个老 bug。现在**全程序只有一个版本号真源**
（`core/version.py` 的 `CURRENT_VERSION`），欢迎页、登录窗、
个人中心、设置页全都从它读。

`--selfcheck` 里有一条闸门：用语法树扫 `ui/` 下所有字符串字面量，
**出现写死的版本号就直接判失败**。所以"程序是 1.9、界面写着 1.0"
这种事不会再发生。

### Q5：迁移失败怎么办？

**先别慌，你的旧数据没有被改动。**

程序在迁移前已经做了完整备份，失败时还会把唯一的那个被改动的文件
（`users.json`）回滚回去。你会看到一条错误提示，里面有备份目录的完整路径。

处理办法：

1. 把错误提示里的路径抄下来，去那个 `backup_v...` 文件夹确认内容在；
2. 直接把 `backup_v...\` 里的东西**复制回** `SGMS\` 目录（覆盖同名文件）；
3. 换回旧版 exe 先正常用着，把错误信息反馈给维护者。

> 回滚**只动 `users.json`**：整个迁移过程只改过这一个文件。
> 成绩、意愿、档案全在 `u_xxxx\` 里，迁移从头到尾没碰过。

### Q6：我点了「取消」，没迁移，会有问题吗？

不会。程序会继续运行，旧数据保持原样。**下次启动还会再问一次**，
不会偷偷替你决定。

### Q7：`backup_v...` / `backup_exe\` 那些文件夹能删吗？

能，但建议至少留最近一份。它们占的是磁盘空间，删掉不影响程序运行 ——
但等真出问题那天，能救你的就是它。

### Q8：我想把数据搬到另一台电脑？

把整个 `%LOCALAPPDATA%\SGMS\` 目录拷过去（**必须连 `app.salt` 一起**）。
只拷 `u_xxxx\` 不行 —— 没有 `users.json` 就登录不了，没有 `app.salt`
意愿/班级/档案全部解不开。

> `models\` 可以不用拷（重新下载即可）；`backup_*\` 也不用。

### Q9：AI 模型是什么？一定要下吗？

**不一定要下。** 它是可选的本地学习助手模型（1~3GB）。

★ 而且要说清楚：**v1.8 只做到"把模型下载下来 + 认出来"，
还没有接推理引擎。** 所以下完之后点「评估」仍然会显示
「模型已加载但未配置推理引擎」—— 这是**诚实的状态说明**，不是故障。

不想用了可以在「设置 → AI 助手 → 删除模型」里删掉，不影响任何成绩数据。

### Q10：程序会不会背着我联网？

不会。全部联网行为只有四种，**每一种都要你主动点**：

| 什么时候 | 连哪 |
|---|---|
| 找回密码时点「发送验证码」 | 你的邮箱 SMTP 服务器 |
| 在设置里手动开云端 AI 并点「深度评估」 | 云端大模型（当前是骨架，未实装） |
| 点「检查更新」 | Gitee 的版本号接口（只读一次） |
| 点「开始下载」 | 你勾选的那个文件的下载地址 |

**没有自动更新检查、没有静默下载、没有 telemetry、没有埋点、没有崩溃上报。**
程序启动时**一次网络请求都不发**。

## 四、数据迁移（v1.7 起）

第一次用新版打开旧数据时，程序会检查数据版本：

| 情况 | 程序会做什么 |
|---|---|
| 数据版本 **比程序旧** | 弹窗"检测到旧版数据 (v1.0)，是否迁移？" |
| 数据版本 **和程序一致** | 什么都不弹，直接进主界面 |
| 数据版本 **比程序新** | 弹窗提示"请先更新程序"，**绝不动你的数据** |

点「是」之后，程序会：

1. **先把整个数据目录完整备份一份**（`backup_v{旧版本}_{日期时间}\`）；
2. 再迁移（1.0 → 1.6 → 1.7 → 1.8 **每一跳都只是写个版本标记**，
   成绩、意愿、档案一个字节都不动）；
3. 告诉你备份放在哪，建议重启程序。

**备份失败就拒绝迁移。** 磁盘满了、没有写权限 —— 程序会直接报错并停手，
你的数据保持原样。

★ 这一步发生在**开屏之前**，也发生在**待应用的更新之前** ——
所以"先换程序、再迁数据"这个次序是确定的。

## 五、给维护者：发版时要做什么

1. 改 `core/version.py` 的 `CURRENT_VERSION`（**只改这一行**）；
2. 去 `core/migrator.py` 的 `_STEPS` 补一跳
   （`("1.8", "1.9", _lift_1_8_to_1_9)`）；**没改数据结构就写个空函数**
   —— 不补的话，启动时迁移会报"没有从 v1.8 升级的路径"（实测踩过）；
3. 跑 `build_exe.ps1 -Both` 打包（脚本会自己跑 `--selfcheck` 和 `--bootcheck`）；
4. **在 Gitee 上创建发行版**（不是打 tag！），标签写成 `v1.9`；
5. **在发行版描述里写上下载直链**（格式见 `docs/DISTRIBUTION.md`）——
   不写的话，程序只会退回"打开浏览器让你自己下"，自动更新那一步用不起来。

> ⚠️ 第 4 步别省。`/releases/latest` 在仓库没有任何发行版时返回 **404**，
> 程序就只能报"仓库里还没有发布任何发行版"。
> 打了 tag 但没建 release 也一样 —— 要的是**发行版**，不是 tag。

## 六、程序自带的三层保护

### 数据侧（v1.7 起）

```
① 版本标记  →  ② 迁移前强制备份  →  ③ 失败自动回滚
```

| 层 | 保证什么 | 代码在哪 |
|---|---|---|
| ① 版本标记 | 程序知道你的数据是哪一版，该不该迁 | `core/version.py`、`CryptoStore.init_vault()` |
| ② 强制备份 | 备份失败 → **拒绝迁移**，绝不"先改了再说" | `core/migrator.backup_vault()` |
| ③ 失败回滚 | 迁移中途出错 → 从备份恢复，逐字节还原 | `core/migrator.migrate_store()` |

### 程序侧（v1.8 新增）

```
① 下到 .part  →  ② 校验（大小 / sha256）  →  ③ 先备份再替换
```

| 层 | 保证什么 | 代码在哪 |
|---|---|---|
| ① 只写 `.part` | 下载中断/取消 → **现有 exe 一个字节没动** | `core/updater.download_exe()` |
| ② 下载后校验 | 网盘错误页 / 传坏的文件 → 直接丢弃，不安装 | `core/updater.verify_checksum()` |
| ③ 备份失败拒绝替换 | 拿不到旧 exe 的副本就**不动手** | `core/update_apply.backup_current_exe()` |
| ④ 替换脚本重试 | 复制失败重试 60 秒；全失败则**什么都不做** | `core/update_apply.render_apply_bat()` |

对应的回归测试：

* `%TEMP%\tl_migrate_test.py`（62 项，数据迁移，用真实目录跑完整条链）
* `%TEMP%\tl_apply_probe.py`（17 项，**真的把生成的 bat 跑一遍**验证替换成功）
* `%TEMP%\tl_download_probe.py`（24 项，本地 HTTP 服务器验证续传 / 取消 / 校验）
* `%TEMP%\tl_v18_test.py`（96 项，v1.8 全量回归）
