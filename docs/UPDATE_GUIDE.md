# 成绩单透镜 · 更新与数据迁移指南

> 面向使用者（辅导员）。看完这一页你就知道：**怎么更新程序、数据在哪、
> 为什么换个 exe 数据还在、出问题怎么办。**
>
> 对应版本：v1.7　　最后更新：2026-09-26

---

## 一、最重要的一句话

> **你的数据不在 exe 旁边，在 `%LOCALAPPDATA%\SGMS\` 里。**
> 所以**换 exe 不会丢数据** —— 前提是你别去删那个目录。

```
C:\Users\<你的用户名>\AppData\Local\SGMS\
├── users.json          账号索引（用户名、校验值；**没有明文密码**）
├── app.salt            应用级密钥盐（**别删，删了意愿/班级/档案全打不开**）
├── u_xxxxxxxx\         你的加密数据
│   ├── grades.enc              成绩
│   ├── tags.json.enc           发展意愿标签
│   ├── archive.json.enc        成长档案（学期时间轴）
│   ├── class_XX-1.json.enc     班级成绩快照
│   └── ...                     德育分、名额、AI 设置等
└── backup_v1.0_20260926_170351\    ← 迁移时自动生成的完整备份
```

`AppData` 是 Windows 的隐藏目录。要打开它：
按 `Win + R`，输入 `%LOCALAPPDATA%\SGMS`，回车。

## 二、更新流程（三步）

### 1. 下载新的 exe

打开仓库的发行版页面：

```
https://gitee.com/wuhaotiansystem/transcript-lens/releases
```

> 也可以在程序里点「⚙️ 设置 → 更新 → 检查更新」。
> 程序只会告诉你有没有新版本并帮你打开浏览器，**不会自动下载、不会自动替换**
> —— 这是刻意的：自动替换 exe 有安全和数据风险，本项目明确不做。

### 2. 覆盖旧的 exe

把下载到的新 `transcript-lens.exe` **覆盖**掉旧的那个。

> ⚠️ 覆盖前先把程序**完全退出**（托盘/任务栏里不能还留着）。
> exe 正在运行的话，Windows 会提示"文件被占用"。

**就这一步。** 不需要卸载、不需要重新注册、不需要重新登录。

### 3. 启动，按提示迁移（如果弹了窗）

第一次用新版打开旧数据时，程序会检查数据版本：

| 情况 | 程序会做什么 |
|---|---|
| 数据版本 **比程序旧** | 弹窗"检测到旧版数据 (v1.0)，是否迁移？" |
| 数据版本 **和程序一致** | 什么都不弹，直接进主界面 |
| 数据版本 **比程序新** | 弹窗提示"请先更新程序"，**绝不动你的数据** |

点「是」之后，程序会：

1. **先把整个数据目录完整备份一份**（`backup_v{旧版本}_{日期时间}\`）；
2. 再迁移（当前 1.0 → 1.7 **只是写个版本标记**，成绩、意愿、档案一个字节都不动）；
3. 告诉你备份放在哪，建议重启程序。

**备份失败就拒绝迁移。** 磁盘满了、没有写权限 —— 程序会直接报错并停手，
你的数据保持原样。

## 三、常见问题

### Q1：为什么我换了个 exe，数据还在？

因为数据在 `%LOCALAPPDATA%\SGMS\`，跟 exe 是两个地方。
exe 只是"读数据的工具"，换工具不影响数据本身。

### Q2：迁移失败怎么办？

**先别慌，你的旧数据没有被改动。**

程序在迁移前已经做了完整备份，失败时还会把唯一的那个被改动的文件
（`users.json`）回滚回去。你会看到一条错误提示，里面有备份目录的完整路径。

处理办法：

1. 把错误提示里的路径抄下来，去那个 `backup_v...` 文件夹确认内容在；
2. 直接把 `backup_v...\` 里的东西**复制回** `SGMS\` 目录（覆盖同名文件）；
3. 换回旧版 exe 先正常用着，把错误信息反馈给维护者。

> 回滚**只动 `users.json`**：整个迁移过程只改过这一个文件。
> 成绩、意愿、档案全在 `u_xxxx\` 里，迁移从头到尾没碰过。

### Q3：我点了「取消」，没迁移，会有问题吗？

不会。程序会继续运行，旧数据保持原样。**下次启动还会再问一次**，
不会偷偷替你决定。

### Q4：`backup_v...` 那些文件夹能删吗？

能，但建议至少留最近一份。它们占的是磁盘空间，删掉不影响程序运行 ——
但等真出问题那天，能救你的就是它。

### Q5：我想把数据搬到另一台电脑？

把整个 `%LOCALAPPDATA%\SGMS\` 目录拷过去（**必须连 `app.salt` 一起**）。
只拷 `u_xxxx\` 不行 —— 没有 `users.json` 就登录不了，没有 `app.salt`
意愿/班级/档案全部解不开。

### Q6：点「检查更新」显示"仓库里还没有发布任何发行版"是什么意思？

意思是：**接口通了，程序也能读到仓库，但维护者还没有发布过发行版**
（只有代码提交，没有打包好的 exe 挂在发行版页面上）。

这不是故障，也不是网络问题。等维护者发布了第一个 release，
同样的按钮就会显示"发现新版本 vX"，不需要你改任何设置。

### Q7：程序会不会背着我联网？

不会。全部联网行为只有三种，**每一种都要你主动点**：

| 什么时候 | 连哪 |
|---|---|
| 找回密码时点「发送验证码」 | 你的邮箱 SMTP 服务器 |
| 在设置里手动开云端 AI 并点「深度评估」 | 云端大模型（当前是骨架，未实装） |
| 点「检查更新」 | Gitee 的版本号接口（只读一次） |

**没有自动更新、没有 telemetry、没有埋点、没有崩溃上报。**

## 四、给维护者：发版时要做什么

1. 改 `core/version.py` 的 `CURRENT_VERSION`（**只改这一行**）；
2. 跑 `build_exe.ps1 -Both` 打包（脚本会自己跑 `--selfcheck` 和 `--bootcheck`）；
3. **在 Gitee 上创建发行版**，标签写成 `v1.7` 这种形式。

> ⚠️ 第 3 步别省。`/releases/latest` 在仓库没有任何发行版时返回 **404**，
> 程序就只能报"仓库里还没有发布任何发行版"。
> 打了 tag 但没建 release 也一样 —— 要的是**发行版**，不是 tag。

4. 如果这一版改了数据结构，去 `core/migrator.py` 的 `_STEPS` 里
   **补一跳**（`("1.7", "1.8", _lift_1_7_to_1_8)`）并写对应的变换函数。
   没改结构就不用动它。

## 五、数据安全的三层防护（v1.7 新增）

```
① 版本标记  →  ② 迁移前强制备份  →  ③ 失败自动回滚
```

| 层 | 保证什么 | 代码在哪 |
|---|---|---|
| ① 版本标记 | 程序知道你的数据是哪一版，该不该迁 | `core/version.py`、`CryptoStore.init_vault()` |
| ② 强制备份 | 备份失败 → **拒绝迁移**，绝不"先改了再说" | `core/migrator.backup_vault()` |
| ③ 失败回滚 | 迁移中途出错 → 从备份恢复，逐字节还原 | `core/migrator.migrate_store()` |

对应的回归测试：`%TEMP%\tl_migrate_test.py`（62 项，用真实目录跑完整条链）。
