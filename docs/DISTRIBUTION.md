# 成绩单透镜 · 分发与发版手册

> 面向维护者。看完这一页你就知道：**怎么发一版、文件放哪、
> 程序里那个「检查更新 → 下载 → 重启」是怎么跟发行版对接的。**
>
> 对应版本：v1.8　　最后更新：2026-09-27

---

## 一、先看清楚：谁从哪拿什么

```
                        ┌─────────────────────────────────────┐
                        │  Gitee 仓库                          │
                        │  wuhaotiansystem/transcript-lens     │
                        └──────────────┬──────────────────────┘
                                       │
             ┌─────────────────────────┼─────────────────────────┐
             │                         │                         │
      ┌──────▼──────┐          ┌───────▼────────┐        ┌───────▼────────┐
      │ 源码          │          │ 发行版 Release  │        │ 发行版描述      │
      │ master 分支   │          │ （打 tag + 建） │        │ （markdown 正文）│
      └──────────────┘          └───────┬────────┘        └───────┬────────┘
                                        │                         │
                                        │ 只提供"版本号"            │ 提供"下载直链"
                                        │ tag_name                │ 主程序 / AI模型
                                        │                         │ sha256 / 体积
                                        └───────────┬─────────────┘
                                                    │
                          ┌─────────────────────────▼──────────────────────────┐
                          │  transcript-lens.exe（辅导员的机器）                 │
                          │                                                    │
                          │  ① 点「检查更新」                                    │
                          │     GET /releases/latest  → 404（还没发版时）        │
                          │     GET /releases         → [] 或 [最新那条]         │
                          │     比 tag_name 和 CURRENT_VERSION                  │
                          │                                                    │
                          │  ② 点「开始下载」                                    │
                          │     解析描述正文 → {"main": url, "ai_models": {...}} │
                          │     urllib.request 流式下到 %TEMP%\SGMS_Update\     │
                          │                                                    │
                          │  ③ 点「立即重启」（或下次启动自动接上）                │
                          │     备份旧 exe → 写 update.json → 生成 .bat → 退出   │
                          │     bat: 重试 copy → del 临时文件 → start 新 exe      │
                          └────────────────────────────────────────────────────┘
```

**三条边界**（charter v1.8 第四节）：

| 允许 | 条件 |
|---|---|
| 更新**检查** | 用户点「检查更新」，只读一次 Gitee 接口 |
| 更新**下载** | 用户点「开始下载」，只下他勾选的那几个文件 |
| AI 模型**下载** | 同上（走的是同一个下载器） |
| ❌ 自动更新 / 静默下载 | **永远不做**。启动时一次网络请求都不发 |
| ❌ telemetry / 埋点 / 崩溃上报 | 永远不做 |
| ❌ requests / httpx | 只用 `urllib.request` |

★ **文件本体不放 Gitee 的 release 附件里**（免费版对附件大小和流量都有限制），
而是放**网盘**，Gitee 的发行版描述里只贴**直链**。
程序只认描述里的链接，不关心文件实际存在哪。

## 二、发版 SOP（六步）

### 第 1 步：改版本号（只改一行）

```python
# core/version.py
CURRENT_VERSION = "1.9"
```

★ **只改这一行。** 界面上所有版本号都从这里读，
`--selfcheck` 里有闸门会拦住任何写死在 `ui/` 里的版本号。

### 第 2 步：补迁移链的一跳

```python
# core/migrator.py
def _lift_1_8_to_1_9(data: dict[str, Any]) -> dict[str, Any]:
    """1.8 → 1.9：没有数据结构变化就原样返回。"""
    return data

_STEPS = (
    ("1.0", "1.6", _lift_1_0_to_1_6),
    ("1.6", "1.7", _lift_1_6_to_1_7),
    ("1.7", "1.8", _lift_1_7_to_1_8),
    ("1.8", "1.9", _lift_1_8_to_1_9),      # ← 新增这一跳
)
```

> ⚠️ **别省这一步。** 不补的话，老用户启动时会报
> `MigrationError: 没有从 v1.8 升级的路径` —— 实测踩过（v1.7 → v1.8 时）。

### 第 3 步：打包

```powershell
Get-Process -Name 'transcript-lens*' | Stop-Process -Force
Start-Sleep -Seconds 3          # 句柄释放有延迟，马上重打会被占用
.\build_exe.ps1 -Both
```

脚本会自己跑三道闸门，任何一道不过就直接中止：

1. **打包前**：源码 `--selfcheck`（数据链路 + 12 组策略闸门）；
2. **打包后**：`exe --selfcheck`；
3. **打包后**：`exe --bootcheck`（真实启动流程，退出码本身就是断言）。

产物：

| 目标 | 路径 | 大小量级 | 给谁 |
|---|---|---|---|
| release | `dist\transcript-lens.exe` | ~230MB | **给辅导员的**（单文件、双击就跑） |
| debug | `dist\transcript-lens-debug\` | ~680MB | 自己排查用（带控制台） |

> `dist/`、`build/`、`*.spec` 都在 `.gitignore` 里。**绝不要 `git add` 它们** ——
> `build_exe.ps1` 最后一步会显式检查这一点。

### 第 4 步：打 tag + 建 Release

```powershell
git add -A
git commit -m "feat(v1.9): ..."
git tag v1.9
git push origin master
git push origin v1.9
```

然后**去 Gitee 网页上创建发行版**：

```
仓库 → 发行版 → 新建发行版
  标签版本：v1.9          ← 必须能解析出版本号
  发行版标题：v1.9
  发行版介绍：（见第 6 步）
```

> ⚠️⚠️ **打了 tag 不等于建了 Release。**
> 实测（2026-09-27）：仓库里没有任何发行版时，
> `/repos/.../releases/latest` 返回 **404**，`/releases` 返回 **`[]`**。
> 程序这时会说"仓库里还没有发布任何发行版" —— 那是**实话**，
> 但辅导员什么也更新不了。

### 第 5 步：上传文件到网盘

把 `dist\transcript-lens.exe` 传到网盘（任选：蓝奏云 / 阿里云盘 / 奶牛快传 /
对象存储 / 自己的服务器），**拿到直链**。

| 要求 | 为什么 |
|---|---|
| **直链**，不是"需要点进去的分享页" | 程序要能直接 GET 到字节 |
| 不需要登录 / 提取码 | 同上 |
| 支持 `Range` 请求（断点续传） | 不支持也能下，只是中断后要重头来 |
| 单文件，别打包成 zip / 分卷 | 程序下载的是 exe 本身 |
| 大文件优先选**能长期有效**的 | 描述里的链接是给未来所有用户用的 |

AI 模型（`.gguf`）同样处理，**但可以单独放**（体积大、可选）。

### 第 6 步：在发行版描述里写上下载信息

**这一步决定「自动更新」能不能用。** 描述正文要按下面的格式写
（程序用 `core/updater.parse_release_body` 解析）：

````markdown
## v1.9 更新内容

- 修了什么什么
- 加了什么什么

### 下载

主程序
https://your-netdisk.example.com/transcript-lens-v1.9.exe
sha256: 3f2a1bcd...(64 位十六进制)
大小: 230MB

AI模型-1.5B
https://your-netdisk.example.com/qwen2.5-1.5b-instruct.gguf
sha256: aaaaaaaa...(64 位)
size: 1.2 GB

AI模型-3B
https://your-netdisk.example.com/qwen2.5-3b-instruct.gguf
````

**解析规则**（都实测过）：

| 你写的 | 程序认成 |
|---|---|
| `主程序` / `## 主程序` / `**主程序**` / `- 主程序` | 主程序那一节 |
| `AI模型-1.5B` / `AI 模型 - 3B` / `AI模型：Qwen` | 某个 AI 模块，名字就是 `1.5B` / `3B` / `Qwen` |
| `主程序: https://...` 写在同一行 | 也认 |
| 标题下面第一行是 URL | 就是那一节的链接 |
| `sha256: <64位>` / `SHA256 = <64位>` / 单独一行 64 位哈希 | 校验和 |
| `大小: 230MB` / `size: 1.2 GB` | 显示用的体积 |
| 整段是一段 JSON `{"main": "...", "ai_models": {...}}` | 也认 |

**不写 sha256 会怎样？** 不校验，照样能下（程序会跳过校验）。
**强烈建议写** —— 它是"下回来的文件确实是你要发的那个"的唯一证据。

**一个链接都不写会怎样？** 程序会退回老行为：弹一句
"这个发行版没有提供程序直链，需要到页面上手动下载"，然后打开浏览器。
不会报错，但自动更新那一步用不起来了。

## 二·五、分片发布（v1.8.1 起）

上面第二、五、六步是**网盘直链**那条老路线。v1.8.1 起主程序改走
**Gitee 发行版附件**，于是多了一种做法：**切片**。

**为什么切**：Gitee 社区版**单个附件上限 100MB**（GVP 200MB、单仓库附件总量 1G），
而 onefile exe 是 **240MB 量级** —— 整包传不上去。
发行版页面上自动生成的 `<标签>.zip` / `<标签>.tar.gz` 是**源码包**，不是 exe 附件。

**程序怎么拼**（`core.updater.download_parts()`，清单里写 `app.parts`）：

```
逐片下载 → 每片核自己的 sha256 → 按清单顺序拼接 → 核整体 sha256 与体积
        → 全程只写 <目标>.part，成功才 os.replace（失败/取消绝不动已有 exe）
```

清单里 `app.size` / `app.sha256` 指**整个 exe**，每一片有自己的 `url` / `size` / `sha256`；
`app.url` 在分片模式下**留空**。

★ **第一次升级必须手动拿包。** 老客户端（v1.8）**不认 `app.parts`**，
读到清单会判「缺 `app.url`」→ **安全退回**老的"发行版正文"路线（不会下错东西，
但分片下不了）。所以第一次装到分片版本，要把三片下下来按顺序拼：

```bat
copy /b part1+part2+part3 transcript-lens.exe
```

★ Gitee 附件直链**不认 `Range`**（带 `Range: bytes=0-0` 仍回 200 + 完整一片），
所以**片内**断点续传在这种托管上不生效，**整片级**续传仍然有效
（已校验过的片不发请求）。

> 📖 **完整操作步骤（改版本号 → 打包 → 切片 → 上传 → 填清单 → 挪标签 →
> 端到端验收 → 回滚方案 → 故障对照表）见 [`docs/RELEASE_SOP.md`](RELEASE_SOP.md)。**
> 本节只说"为什么切片、程序怎么拼"，操作细节一律不在这里重复。

## 三、AI 模型的分发策略

模型文件（GGUF）和主程序是**两条独立的线**，理由：

| | 主程序 | AI 模型 |
|---|---|---|
| 大小 | ~230MB | 1.2GB ~ 2.8GB |
| 必需性 | **必需** | **可选**（不下也能用全部功能） |
| 更新频率 | 每次发版 | 几乎不变（模型本身很稳定） |
| 放哪 | 网盘直链 | 网盘直链（可以不同网盘） |
| 程序里的位置 | 替换 exe | `%LOCALAPPDATA%\SGMS\models\<名字>\` |

**为什么模型不放程序目录**：

1. 1~3GB 进仓库不现实；
2. 打包成 exe 后程序目录常常不可写（`C:\Program Files\`）；
3. 数据目录本来就是"这台机器上属于本程序的东西"的家，模型和它同级最好解释。

**分发建议**：

* 在发行版描述里**列全**所有可用模型（名字 + 体积），
  程序会把它们显示成勾选框；
* 模型没更新时**不必**在新发行版里重复贴链接 ——
  但注意：程序只读**最新那个发行版**的描述，
  所以**要一直贴着**，否则老版本发行版里的模型链接会"消失"；
* 模型文件名请用 `.gguf` 结尾（程序靠扩展名认出"这是个模型"）；
* 给模型也写 `sha256` —— 大文件传坏的几率比小文件高得多。

**模型下载的安全机制**（和主程序同一套）：

```
下载 → models\temp\<名字>__<文件名>       （全程写 .part，中断可续传）
     → 校验 sha256（如果描述里给了）
     → 校验体积 >= 1MB（防网盘错误页）
     → 搬到 models\<名字>\<文件名>        （原子改名）
```

`installed_models()` 的判据是"目录里有一个**非空**的 `.gguf`" ——
所以下载中途断电不会让设置页显示一个装好的假模型。

## 四、发版检查清单

发之前逐条对一遍：

- [ ] `core/version.py` 的 `CURRENT_VERSION` 改成新版本了
- [ ] `core/migrator.py` 的 `_STEPS` 补了一跳（哪怕是空函数）
- [ ] `main.py --selfcheck` 全绿（**尤其那 12 组策略闸门**）
- [ ] `git status` 干净，`dist/` `build/` 没被 `git add`
- [ ] `Get-Process -Name 'transcript-lens*' | Stop-Process -Force` 之后再打包
- [ ] `build_exe.ps1 -Both` 两个目标都通过 selfcheck + bootcheck
- [ ] **Gitee 上建了发行版**（不是只打 tag）
- [ ] 发行版**描述里有 `主程序` + 直链**
- [ ] 描述里的 `sha256` 和实际文件对得上（`certutil -hashfile 文件 SHA256`）
- [ ] 下载链接**匿名可访问**（开个无痕窗口试一下）
- [ ] AI 模型的链接（如果有）也贴上了
- [ ] 拿一台**干净机器**（或新建 Windows 用户）跑一遍：
      能启动、能检查更新、能下载、能替换

### 验证替换真的成功了

在一台测试机上：

```powershell
# 1. 记下当前版本
.\transcript-lens.exe --selfcheck   # 看报告里的 CURRENT_VERSION

# 2. 走一遍「检查更新 → 开始下载 → 立即重启」

# 3. 确认新版本起来了
.\transcript-lens.exe --selfcheck

# 4. 确认备份存在
dir "$env:LOCALAPPDATA\SGMS\backup_exe"

# 5. 确认临时文件清干净了
dir "$env:TEMP\SGMS_Update"
```

第 5 步里**只应该剩 `apply_update.log`** ——
`update.json`、`apply_update.bat`、下载下来的 exe 都该被脚本删掉了。

## 五、出问题时的排查顺序

| 现象 | 先看哪 |
|---|---|
| 点检查更新报"检查失败" | 换台机器/手机热点试同一个链接；Gitee 接口可能限流 |
| 说"还没有发布任何发行版" | 仓库 → 发行版，确认**建的是发行版不是 tag** |
| 点开始下载没反应 | 描述里的直链是不是**分享页**而不是直链 |
| 下载总是失败 | 链接是不是需要登录 / 提取码；是不是跳转到了 HTML 页面 |
| 提示"文件太小，不是程序本体" | 直链返回的是网盘错误页 —— 链接过期了 |
| 提示"sha256 校验不一致" | 描述里的哈希贴错了，或者文件传坏了 |
| 点了立即重启但版本没变 | `%TEMP%\SGMS_Update\apply_update.log` |
| 重启后程序没自动打开 | 同上；替换是成功的，只是 `start` 那一步失败了，手动打开即可 |
| 备份失败、拒绝替换 | `%LOCALAPPDATA%\SGMS\` 所在磁盘满了 / 没写权限 |
